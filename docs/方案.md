# 方案：为什么这么做

> 需求：在 iPhone 上随时看房贷（商贷 / 组合贷）的剩余本金、已还本息、剩余本息、已产生利息、每期还款额、期数；能配置本金、还款方式、利率、提前还款；能"定时自动增加还款记录"。**不开发 App、不做小程序，最好有桌面小组件。**

## 一、先拆需求

这个需求看着像"记账 App"，其实不是。真正要回答的问题只有两个：

1. 我现在欠银行多少钱？（剩余本金）
2. 我什么时候能还完、还要付多少利息？（剩余本息 / 结清时间）

而这两个数，**银行合同一签就确定了**，唯一会变的是「利率调整」和「提前还款」这两类事件。

所以「每期还款记录」不是数据源，而是**合同的衍生结果**。想清楚这一点，整个方案就简单了：

> 存 5 个参数 + 几个事件，其余全部按日期推导。不需要定时任务，不需要数据库，不需要联网。

## 二、形态选择

| 方案 | 结论 |
| --- | --- |
| 原生 iOS App | 开发 + 上架 + 每年续费 $99，为了看一个数字不值 |
| 微信小程序 | 明确排除；且打开路径比网页还长 |
| Excel / Numbers | 公式能做，但手机上改参数痛苦，加不到桌面 |
| Notion / 飞书表格 | 要联网、要加载、小组件不可定制 |
| 记账类 App（随手记等） | 记的是流水，不建模合同，提前还款算不准 |
| **PWA 网页 + Scriptable 小组件** | ✅ 选它 |

**PWA**：一个静态 HTML，Safari「添加到主屏幕」后全屏运行、有图标、没有地址栏，体验接近原生。改一行 CSS 就能调 iPhone 上的字号和间距，这是原生开发做不到的迭代速度。

**Scriptable 小组件**：iOS 桌面小组件只能由 App 提供。Scriptable 是"用 JS 写小组件"的壳子 App —— 我们写脚本、它负责渲染和刷新。这样既满足了"要小组件"，又没有开发 App。计算引擎内联进脚本，**离线也能算**。

## 三、展示：三个入口

1. **主屏图标（PWA）** —— 完整看板，四个 tab：概览 / 还款计划 / 贷款设置 / 数据同步。
2. **桌面小组件** —— 小号只看"剩余本金 + 本期应还"，中号加"已还利息 / 剩余利息 / 下次还款日"，大号再列每笔贷款。
3. **导出 JSON / 复制配置** —— 换设备、备份、喂给小组件。

信息层级是刻意压过的：概览页第一屏必须能读完「还欠多少、这次还多少、还要还多久」，其余的往下一层放。

组合贷默认合并看，但「统计范围」可以切到只看公积金或只看商贷 —— 做法是**先过滤贷款、再整套重算**，不是按比例拆分几千个数字，所以每一栏都能对上单笔合同。还款计划按 30 期分页，顶部和底部都有翻页条。

## 四、计算：模拟，而不是套公式

闭式公式只对"从不提前还款、利率永不调整"成立。真实场景一旦插入事件，就必须**逐期模拟**：

```
balance   = 本金
r         = 当期年利率 / 1200
月供      = P·r·(1+r)ⁿ / ((1+r)ⁿ − 1)        // 等额本息
for 第 p 期 in 1..n:
    date     = 首次还款日 + (p−1) 个月
    利率      = 该日期生效的利率（应用 rateChanges）
    interest = balance × 利率 / 12
    principal= 月供 − interest                  // 等额本金则 = 本金 / n
    balance -= principal
    if 有提前还款落在本期之后:
        balance -= 提前金额
        缩期限 → 月供不变，用 periodsFor() 反解剩余期数
        降月供 → 期限不变，用新余额重算月供
    记录这一期
```

每期金额**四舍五入到分**，末期用余额抹平。这带来一个可接受的副作用：100 万 / 4.9% / 30 年的总利息是 910,614.92，比理论值 910,616.19 少 1.27 元 —— 差异来自月供取整到分。**模拟比闭式公式更接近银行实际扣款**，这 1 块多的差就是证据。

**已还 / 未还全部按日期判断**，不看有没有"录入过"：

- 已还期数 = 还款日 ≤ 基准日的期数（还款日当天算已还）
- 已产生利息 = 已还各期利息 + 当期利息 × 已过天数 / 当期天数（月中打开也能看到"这个月已经产生多少利息"）
- 把基准日改到明年，立刻能看到"明年这时候还欠多少"

引擎是纯函数、UMD 打包，浏览器 / Node / Scriptable 共用一份代码，不会出现"网页和小组件算得不一样"。

## 五、存储：一个 2KB 的 JSON

```json
{
  "v": 1,
  "name": "我的房贷",
  "loans": [
    {
      "name": "公积金贷", "kind": "公积金",
      "principal": 600000, "annualRate": 2.85, "termMonths": 300,
      "method": "equal_installment", "firstPaymentDate": "2024-06-20",
      "rateChanges": [{ "fromDate": "2026-06-20", "annualRate": 2.6 }],
      "prepayments": [{ "date": "2026-01-20", "amount": 100000, "mode": "shorten_term" }]
    },
    { "name": "商贷", "kind": "商贷", "principal": 400000, "annualRate": 4.2, "...": "..." }
  ]
}
```

- **默认零后端**：存 `localStorage`，数据不出手机。
- **备份**：导出 JSON；换机导入。
- **多设备 / 小组件自动更新**：把同一份 JSON 放进你自己的**私有** GitHub 仓库（`PUT /repos/:owner/:repo/contents/:path`），网页「上传 / 拉取」，小组件用同一个文件。这条路不用自己架服务器，密钥是一枚只对那一个仓库有 Contents 权限的 fine-grained token。
- **备选**：不想用 GitHub，可以部署一台 Cloudflare Worker + KV（`worker/`），一个 `GET/PUT /api/state`，Bearer 鉴权，免费额度一个人用不完。

为什么不上数据库 / 后端？因为数据量是**几 KB、一年改几次**。上后端只会多出服务器、账号、隐私三个负担。GitHub 仓库刚好满足"我自己可控 + 有版本历史 + 不写代码也能同步"。

## 六、取舍与已知限制

- **不记流水**，所以无法对账"银行这个月到底扣了多少"。真要精确对账，再加一个可选的 `actualPayments` 覆盖表即可（引擎留了扩展位，当前没做）。
- **提前还款按"当期先照常还月供、再还提前款"** 处理。银行实际是按日计息、当天先结息再还本，差额通常在几元以内。已还本息里，提前还款按**提前还款日**计入（不是等下一期），所以「已还 + 剩余 = 总额」始终成立。
- **LPR 不会自动抓**，需要你在降息后手动加一条「利率调整」。
- 不建模罚息、按月冲还贷、等额本息与等额本金中途互转。

## 七、还能往哪走

- 加「实际扣款对账」：记录银行真实金额，差额提醒。
- 加「提前还款试算」：输入 10 万，直接对比缩期限 vs 降月供各能省多少（引擎已经有 `savedInterest`，差一个 UI）。
- 小组件加锁屏版本（iOS 16+ `accessoryRectangular`）。
- 多套方案对比（"如果现在商转公"）。
